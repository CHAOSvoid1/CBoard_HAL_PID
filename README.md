# CBoard HAL M2006/M3508 PID / 滑模闭环控制

> **项目定位：单独电机测试台。** 使用一块 RoboMaster C 型开发板作为唯一主控，
> 一次连接并闭环测试一台 M2006+C610 或 M3508+C620。它用于验证电机、电调、
> CAN、编码器反馈和 PID 参数，不是步兵/英雄等整车工程。

本工程基于 STM32F407IGH6（RoboMaster 开发板 C 型）和 STM32 HAL 库，支持：

- M2006 + C610、M3508 + C620；
- CAN1/CAN2，1 Mbps；
- 电机 ID 1~8；
- PID 与滑模两套可选控制：速度 STSMC、位置终端滑模 + 速度 STSMC；
- 反馈超时、过温、输出限幅和停机保护；
- USART1 或 USART6；
- VOFA+ FireWater 与 JustFloat 两种协议；
- 串口在线切换控制算法、模式、目标值、PID/滑模参数和波形格式。

## 测试台适用范围与限制

- 主控固定为 RoboMaster 开发板 C 型（STM32F407IGH6）；
- 被测对象仅为 `M2006+C610` 或 `M3508+C620`；
- 默认一次只测试一台电机，界面中选择的电调 ID 就是唯一闭环对象；
- CAN 控制帧仍按 DJI 的 4 电机分组发送，但除所选 ID 外的 6 个字节始终为 0；
- C 板使用独立稳定电源，电调动力侧按其规格供电，C 板、电调和 USB-TTL 必须共地；
- 首次测试必须空载或架空电机，并确保可以随时点击 `STOP 急停`；
- 速度环稳定后才允许调位置环；位置模式前先执行 `ZERO`；
- 默认电流限制是测试用保守值，不代表电机额定能力，也不建议一开始调大；
- 若要同时控制多台电机，应另做多电机数据结构、分组发送和独立 PID，本项目不承担该用途。

### 两种电机的特化差异

| 项目 | M2006 + C610 | M3508 + C620 |
|---|---|---|
| 协议电流满量程 | ±10000 raw | ±16384 raw |
| 本工程默认安全限幅 | ±3000 raw | ±4000 raw |
| 默认减速比 | 36:1 | 3591/187，约 19.2:1 |
| 温度反馈 | 不作为有效温度使用 | 使用反馈帧 byte6，85 °C 停机 |
| 推荐首次速度目标 | 100~200 rpm | 100~200 rpm |

这里的转速反馈为电机转子转速；位置角度经过减速比换算，表示减速箱输出轴累计角度。

## 0. 可视化测试工具

界面采用仪器工作台式布局：左侧是固定测试流程，顶部状态条持续显示 PC 串口、MCU 数据、CAN 电机和运行状态；中部依次保留固件配置、硬件连接、通讯终端、闭环控制与量化自检；分析区使用两张全宽时域图，保证坐标与多通道曲线拥有足够空间。布局参考现代 Web 串口分析工具的信息层级，但所有控制命令、测试步骤和本地后台接口均保持不变。

曲线分析区采用多通道时域工作台：速度图显示目标/实际转子转速；位置图默认显示目标/实际减速箱输出轴角度，并可点击通道标签叠加转子累计角度或电流。M3508 转子累计角度由输出轴角度乘以 `3591/187`，M2006 乘以 `36` 得到。该转子角度是相对当前位置清零后的换算值；位置闭环的被控量始终是减速箱输出轴角度。CSV 同时导出目标输出轴、实际输出轴和换算转子位置。

直接双击工程根目录中的 **`启动电机调试工具.exe`**。这是压缩包中唯一的启动入口，
它会在本机 `127.0.0.1` 随机端口启动服务并自动打开默认浏览器。重复双击不会产生多个
服务进程，而是重新打开已经运行的页面。服务只监听本机回环地址，不对局域网开放。

工具由 Windows 原生 C# 程序和一个本地 HTML 页面组成，不依赖互联网、Node.js、Python、
PowerShell 或前端 CDN；Windows 10/11 解压后即可运行。浏览器受安全限制，不能直接访问
电脑串口、修改 `app_config.h` 或启动 Keil，因此本地后台是必要组件，但使用者不需要单独
配置或操作它。启动器不再创建系统托盘图标；浏览器页面通过本机心跳保持服务，关闭最后一个页面后会自动断开串口并退出。正常刷新时新页面的心跳会取消退出，但串口仍按安全要求断开，需重新连接。旧入口已移入
`Tools/Legacy`，仅用于回退，不应作为日常入口。

工作台末尾的“控制理论与算法映射”是独立预研区。在闭环控制中选择 PID 或滑模后，可点击“展开算法说明”查看完整数据流、变量来源、固件对应公式与后续对比试验方法。该区只做说明，不会发送命令、改写固件或影响当前测试。

工程文件夹可以移动到任意磁盘和任意路径，工具通过自身位置寻找 `User_Files` 和
`MDK-ARM/CBoard.uvprojx`，不依赖固定工程路径。Keil 会依次从环境变量、PATH、

### 控制效果分级

自动评分采用约 200 ms 的 EMA 滤波结果计算动态超调、稳态误差、调节时间和 RMSE，同时单独显示原始反馈纹波，避免把 C620 的单点测速尖峰误判为真实机械超调。固件控制端另使用约 20 ms 的反馈低通抑制追噪，串口遥测仍保留未经滤波的原始速度。

| 等级 | 总分 | 滤波超调参考 | 稳态误差参考 | 建议评价 |
|---|---:|---:|---:|---|
| A 优秀 | 90–100 | ≤5% | ≤2% | 高质量空载/轻载控制，仍需带实际负载验证 |
| B 良好 | 75–89 | ≤10% | ≤5% | 满足多数一般执行机构需求 |
| C 可用 | 60–74 | ≤20% | ≤10% | 可用于一般动作，建议继续调参 |
| D 需调参 | 40–59 | ≤40% | ≤20% | 只适合初步动作验证 |
| F 不合格 | 0–39 | >40% 或失控 | >20% | 禁止带载使用 |

总分从 100 分扣除超调、稳态误差、滤波纹波、上升时间和调节时间五项。未进入稳态按 25 分扣除，避免出现“未稳定反而比晚稳定扣分少”的倒挂。无反馈、反向失控、过温或保护停机属于安全失败，不因总分较高而通过。

等级不是电机本体的永久标签，而是“电机 + 电调 + 供电 + 负载 + 控制参数”在当前工况下的结果。正式评价至少重复三次，并补做正反转和实际负载测试。

## 1. 硬件连接

### CAN1（默认）

| C 板 | 功能 |
|---|---|
| PD0 | CAN1_RX |
| PD1 | CAN1_TX |
| CAN1_H | 接 C610/C620 CAN_H |
| CAN1_L | 接 C610/C620 CAN_L |

CAN 总线两端应各有 120 Ω 终端电阻。电调和 C 板必须共地。C610/C620 CAN 波特率固定为 1 Mbps。

### VOFA 串口（默认 USART6）

| C 板 | USB-TTL |
|---|---|
| PG14 / USART6_TX | RX |
| PG9 / USART6_RX | TX |
| GND | GND |

使用 3.3 V TTL，参数为 115200-8-N-1、无流控。USART1 也已配置：PA9/TX、PB7/RX。

## 2. CubeMX 配置检查

- HSE：12 MHz；
- PLL：M=6、N=168、P=2，SYSCLK=168 MHz；
- APB1=42 MHz，APB2=84 MHz；
- CAN：APB1 42 MHz / `3 * (1 + 10 + 3)` = 1 Mbps；
- CAN1：PD0/PD1，AF9；
- CAN2：PB5/PB6，AF9；
- USART1：PA9/PB7，AF7；
- USART6：PG14/PG9，AF8；
- TIM1：168 MHz / 168 / 1000 = 1 kHz；
- CAN RX 中断优先级 0，TIM1 优先级 1，UART 优先级 2。

CAN 已开启自动重发和 Bus-Off 自动恢复。`.ioc` 与生成后的 HAL 初始化代码均已同步修改。

## 3. 选择电机、ID、CAN 和串口

修改 `User_Files/app_config.h`：

```c
#define APP_MOTOR_TYPE  MOTOR_TYPE_M3508  // 或 MOTOR_TYPE_M2006
#define APP_MOTOR_ID    5U                // 电调拨码 ID 1~8；默认与参考工程一致
#define APP_USE_CAN1    1U                // 1=CAN1，0=CAN2

```

电流安全限幅默认值：

- M2006：±3000 raw（协议满量程 ±10000）；
- M3508：±4000 raw（协议满量程 ±16384）。

先在空载条件下确认反馈方向、急停和限幅，再逐步提高限制。

## 4. CAN 协议

| 电调 ID | 控制帧 ID | 数据位置 | 反馈帧 ID |
|---|---:|---:|---:|
| 1 | 0x200 | byte 0~1 | 0x201 |
| 2 | 0x200 | byte 2~3 | 0x202 |
| 3 | 0x200 | byte 4~5 | 0x203 |
| 4 | 0x200 | byte 6~7 | 0x204 |
| 5 | 0x1FF | byte 0~1 | 0x205 |
| 6 | 0x1FF | byte 2~3 | 0x206 |
| 7 | 0x1FF | byte 4~5 | 0x207 |
| 8 | 0x1FF | byte 6~7 | 0x208 |

反馈解析：编码器、转速、电流和温度。编码器跨零点时进行圈数累计；位置环使用减速箱输出轴角度：M2006 默认减速比 36，M3508 使用 `3591/187`。

## 5. 控制逻辑

TIM1 每 1 ms 执行一次控制：

```text
速度模式：目标转速 -> 速度斜坡 -> 速度 PI + 分段前馈 -> 电流指令 -> C610/C620

位置模式：目标输出轴角度 -> 位置 P -> 限速与速度斜坡
                                      -> 速度 PI + 分段前馈 -> 电流指令
```

位置模式附加安全策略：

- 切换控制模式会先输出零电流并停止，位置模式初始目标取当前位置；
- 当前 M3508 位置外环使用 `36/0/0`，位置往返报告在 ±1200 rpm 限制下两方向得到
  99～100 分，因此将位置内环速度上限提高到 ±3000 rpm；M2006 保持 ±1500 rpm；
- 位置外环目标速度不是阶跃送入速度环：M3508 使用加速 4000、减速/换向 6000 rpm/s
  的斜坡，M2006 使用 2400/3600 rpm/s，防止大角度换向瞬间给出满速电流；
- ±0.3° 位置死区内输出零速度，减少静止时因编码器量化造成的偶发动作；
- 每 200 ms 检查位置误差趋势。误差大于 10° 且继续增大超过 5° 时自动停机，
  `STATUS` 中 `pos_guard=1`，用于防止反馈方向错误导致持续疯转；
- 位置目标硬限制为 ±720°。首次测试建议置零后使用 ±30°。

选择滑模算法时：

```text
速度模式：目标转速 -> 超螺旋滑模 STSMC -> 电流指令

位置模式：目标输出轴角度 -> 非奇异终端滑模位置律 -> 目标转速
                                                    -> STSMC -> 电流指令
```

速度 STSMC 使用 `s = target_rpm - measured_rpm`，连续边界层 `sat(s/phi)` 代替理想
`sign(s)`，控制律为 `u = k1*sqrt(|s|)*sat(s/phi) + z`、
`z_dot = k2*sat(s/phi)`。积分状态和最终电流均受安全限幅约束。

位置外环采用非奇异终端滑模思想构造连续位置收敛速度：
`omega = beta*|e|^(3/5)*sign(e) + eta*sat(e/phi)`，再按减速比换算成电机转子 rpm。
它是适合当前测试台的工程化 NFTSMC 位置律。由于项目尚未辨识转动惯量、摩擦、负载扰动和
电流—转矩增益，没有加入文档中依赖精确对象模型的等效补偿项，因此不能把当前默认参数视为
严格证明有限时间稳定的最终参数。若完成参数辨识，可在 `control.c` 中继续加入模型补偿。

只有收到有效反馈并执行 `RUN` 后才允许非零输出。发生以下情况时强制发送零电流：

- `STOP`；
- 超过 100 ms 没有电机反馈；
- M3508 温度达到 85 °C；
- 控制模式为 STOP。

## 6. 串口命令

每条命令以回车或换行结束：

```text
HELP
PING
STATUS
RUN
STOP
ZERO
MODE:SPEED
MODE:POSITION
SPEED:1000
POS:90
PID:SPEED,2.5,1.5,0.0
PID:POSITION,8.0,0.0,0.0
CTRL:PID
CTRL:SMC
SMC:SPEED,60,500,30
SMC:POSITION,8,20,2
FORMAT:FIREWATER
FORMAT:JUSTFLOAT
```

`PING` 正常应回应 `event:pong_uart_ok`，它只证明电脑到 C 板以及 C 板到电脑的 UART
双向通讯正常。`STATUS` 回应示例：

```text
diag:uart=USART1,can_online=1,target_rx=1250,bus_rx=1250,last_id=0x201,can_tx_ok=830,can_tx_fail=0,can_esr=0x00000000,mode=1,enabled=1,controller=PID
```

- `can_online=1`、`target_rx` 持续增加：已收到当前电调 ID 的反馈；
- `bus_rx=0`：CAN 总线上没有收到任何标准数据帧，检查 CAN1/CAN2、CAN_H/L、终端电阻和电调动力供电；
- `bus_rx>0` 但 `target_rx=0`：物理总线正常，但收到的是其他 ID；根据 `last_id` 检查电调拨码；
- `can_tx_fail` 增加或 `can_esr` 非零：检查 CAN 物理层、波特率和总线状态；
- 网页显示串口已连接但 RX 始终为 0：COM 口虽已打开，但 MCU 没有回传，应检查 TX/RX
  交叉、共地、USART1/USART6 选择、115200 波特率以及是否已烧录最新版固件。

为排除丝印或配置选择问题，诊断固件会同时监听 USART1 和 USART6；哪个串口先收到命令，
后续回应与遥测就自动切换到哪个串口。上电时两个串口都各发送一条 `boot:` 消息。

单位在固件、串口和网页中统一为：速度是电机转子 `rpm`，位置是经过减速比换算后的
减速箱输出轴角度 `°`。M2006 速度目标限制为 ±3000 rpm，M3508 为 ±7400 rpm；位置目标限制为 ±720°。

推荐首次测试顺序：

```text
STOP
MODE:SPEED
SPEED:200
RUN
```

确认方向和反馈正常后，再逐步增大目标转速。位置模式前执行 `ZERO`，将当前位置设为输出轴 0°。

滑模首次测试建议：先用 PID 验证反馈方向和急停，再发送 `CTRL:SMC`（此时自动 STOP），
保持 `MODE:SPEED`、目标 100 rpm 后重新 `RUN`。参数含义如下：

| 命令 | 参数 |
|---|---|
| `SMC:SPEED,k1,k2,phi` | STSMC 根号项增益、积分到达增益、速度边界层 rpm |
| `SMC:POSITION,beta,eta,phi` | 终端收敛增益、到达速度增益、位置边界层 ° |

增大 `k1/k2` 会增强速度响应和抗扰，但也更易出现电流波动；增大 `phi` 可减小抖振但会扩大
边界层内误差。先调速度 STSMC，再进入位置模式调 `beta/eta`。任何振荡、异响或持续限流都应
立即 STOP，并降低目标值和增益。

## 7. VOFA+ FireWater

默认格式。VOFA+ 选择 FireWater，串口 115200。输出格式：

```text
motor:target_speed,actual_speed,target_position,actual_position,current,temp,online,rx_count
```

例如：

```text
motor:1000.000,986.000,0.000,12.345,830,42,1,12560
```

FireWater 中可使用 `motor` 标签，也可直接观察各逗号分隔通道。

## 8. VOFA+ JustFloat

先在文本终端发送：

```text
FORMAT:JUSTFLOAT
```

然后把 VOFA+ 协议切换为 JustFloat。帧包含 8 个小端 float，帧尾为 `00 00 80 7F`：

| 通道 | 内容 |
|---:|---|
| 0 | 目标速度 rpm |
| 1 | 实际速度 rpm |
| 2 | 目标位置 ° |
| 3 | 输出轴实际位置 ° |
| 4 | 电流指令 raw |
| 5 | 温度 °C |
| 6 | 在线状态 0/1 |
| 7 | 当前速度控制器输出（PID 或 STSMC） |

切换回 FireWater 时，在串口助手发送 `FORMAT:FIREWATER`；因为 JustFloat 模式下串口仍保持命令接收，所以可以直接发送 ASCII 命令。

## 9. PID 整定

1. 先使用速度模式，位置 PID 暂不参与。
2. 速度环先设 `Ki=0、Kd=0`，逐渐增加 `Kp`，直到响应足够快但不持续振荡。
3. 缓慢增加 `Ki` 消除稳态误差；电流经常顶到限幅时不要继续增益。
4. 切换位置模式，从较小的位置环 `Kp` 开始；位置环输出是目标转速，已限制为 ±3000 rpm。
5. `Kd` 对编码器噪声敏感，通常保持很小或为 0。

README 中的 PID 值是安全起点，不是所有负载下的最终参数。建议先运行网页中的速度阶跃
测试并导出报告：响应慢且未限流时小步增加 `Kp`；稳态误差大时小步增加 `Ki`；超调或
振荡明显时优先降低 `Kp/Ki`。速度环达到可接受评分后，再运行位置阶跃测试调整位置外环。
自动评分用于同一硬件条件下的相对比较，不替代人工观察、限流和急停；程序不会在未经
确认时自动写入 PID 参数。

### M3508 重新调参流程

第二轮扫描中，`2.5/1.5` 获得约 0.88 s 上升时间、21% 超调和 64.73 RMSE，优于
`2.0/1.5`，因此作为新的中间推荐值写入固件。第三轮扫描比较 `2.5/1.2`、
`2.5/1.5`、`3.0/1.0`、`3.0/1.2`，通过提高比例并降低积分来减小静摩擦期间的积分蓄积。
每组运行时间延长到 8 秒，完整遥测保存在 `pidSweepRuns[].candidates[].telemetry`。

报告从第三轮开始保证每类测试独立携带原始遥测：速度/位置自检位于
`results.<type>.telemetry`，多段辨识位于 `identificationRuns[].telemetry`，候选扫描位于
`pidSweepRuns[].candidates[].telemetry`。因此后续只需发送 JSON，不需要截图。

当前 M3508+C620 通用速度参数为 `1.15/0.35/0`。它与分段速度前馈配合使用，不能与早期
纯 PI 参数直接比较。自动验收使用 `0→1000→4000→6000→3000→0 rpm` 高速阶梯和
最高 `±6000 rpm` 的正反转流程；`APP_SPEED_TARGET_LIMIT_RPM` 仍保持 `7400 rpm`，
6000 rpm 只是自动测试档位，并未降低手动安全限速。

网页中的“应用 PID”通过串口发送 `PID:SPEED,Kp,Ki,Kd` 或
`PID:POSITION,Kp,Ki,Kd`。固件收到命令后更新 MCU RAM 中的 PID 结构并复位该环积分状态；
它不会擦写 Flash。断电或复位后恢复编译进固件的默认参数，只有重新编译烧录才会永久改变默认值。

X 轴刻度始终以全部遥测中的最新样本为 `0 s`。范围条回看历史时，刻度会同时显示对应的
负时间区间，例如 `-37.0 s ～ -7.2 s`，不会再把历史窗口右端错误地重标为 `0 s`。

### M3508 速度前馈

当前 M3508 速度内环是“目标前馈 + 反馈 PI”：前馈基础项为 `200 raw`，0～1000 rpm 的
斜率为 `0.30 raw/rpm`，1000 rpm 以上的增量斜率为其 55%，即 `0.165 raw/rpm`。
前馈只根据目标速度估算基础电流，不是反馈；PI 根据滤波后的实测速度误差补偿负载、电压和
电机/电调个体差异。两路在电流限幅前相加，总电流仍受 `APP_CURRENT_SAFE_LIMIT` 限制，
M2006 不启用该 M3508 专用前馈。

直接速度模式的目标斜坡为加速 `1200 rpm/s`、减速或换向 `1800 rpm/s`。斜坡尚未到达最终
目标时冻结积分，避免把有意设置的参考变化积成超调；目标稳定后开放带抗饱和的积分以消除
稳态误差。位置模式的速度内环仍使用窄积分区间。网页流程图 v3 改为紧凑主通路，并用两行
分别说明反馈与前馈支路，避免完整 SVG 在窄窗口中显得拥挤。

速度档位评分按遥测中的实时斜坡指令与实测速度计算跟踪误差，并在指令到档后计算超调和稳态
误差；不会再把尚未完成的斜坡误判为对最终目标的大偏差。正反转测试按
`0→正转→0→反转→0` 逐档执行，只有遥测确认内部斜坡到档后才开始稳定保持计时。测试报告
继续保存全部原始遥测点。

## 10. 编译与排障

使用 Keil 打开 `MDK-ARM/CBoard.uvprojx`，执行 Rebuild。新增源码已加入三个 `User_Files` 分组及包含路径。

若电机不转：

1. FireWater 的 `online` 应为 1，`rx_count` 应持续增加；
2. 确认电调 ID 与 `APP_MOTOR_ID` 一致；
3. 确认所接 CAN 口与 `APP_USE_CAN1` 一致；
4. 测量 CAN_H/CAN_L，检查终端电阻和共地；
5. 确认发送过模式命令、目标命令和 `RUN`；
6. 查看 `current` 是否为非零；
7. 如果速度方向与电流方向相反，检查电机三相线或反馈符号，禁止直接加大 PID。

若串口没有输出：

1. USART6 使用 PG14/PG9，不是 ST-Link 虚拟串口；
2. TX/RX 必须交叉并共地；
3. 复位时应出现帮助文本；
4. 普通串口助手不能正确显示 JustFloat 二进制数据，排障时先使用 FireWater。
